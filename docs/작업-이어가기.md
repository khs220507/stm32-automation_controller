# 작업 이어가기

대화를 재개할 때 가장 먼저 확인하는 진행 메모다. 사용자 결정, 완료 보고와 다음 행동을 남긴다. 공식 요구사항·시험 판정은 관리 문서를 따르며, 이 메모가 대신하지 않는다.

## 현재 위치

- 현재 작업: 사용자 요청으로 RS-485 디버깅은 계획만 남기고 보류. TX/RX 교환 후에도 COM4 PING 무응답·USART1 수신 0인 상태에서 다음 재개를 기다린다.
- 완료한 준비: 납땜 완료 및 AT044 TXD↔PB6(CN10-17), RXD↔PB7(CN7-21) 연결 완료(2026-09-14 사용자 보고). 전원·A/B를 포함한 전체 배선의 실물 검증을 뜻하지 않는다.
- 최신 배선 변경 보고: 이후 사용자가 TX/RX 쪽을 서로 뒤집었다고 알렸다. 이전 연결 기준으로는 AT044 TXD↔PB7, RXD↔PB6에 해당하지만 실제 최종 단자 사진은 아직 확인하지 않았다. 위의 최초 연결 기록과 구분한다.
- 완료한 구현: USART1 115200 8N1 수신·응답, TCP/RS-485 별도 파서와 응답 경로, WPF 연결 방식/COM 선택·시간 초과·기존 센서 표시. C 호스트 시험과 WPF 122개 시험 성공. 최종 펌웨어 다운로드·검증·리셋 완료.
- 실제 결과: COM4(CH340) PING 무응답, USART1 수신/오류 카운터 0. WPF에서 500 ms 시간 초과·연결 해제 표시 확인. COM3 UART PONG 및 TCP 센서 응답은 확인했다. RS-485로 센서 데이터가 표시된 것은 아직 아님.
- 다음 위치: 아래 디버깅 계획의 1번부터 재개. 사용자가 멀티미터와 로직애널라이저를 보유한다고 보고했다. PC 쪽 USB 변환기 종류와 최종 A/B·TX/RX 연결은 실물 확인 전이다. 사용자 재개 요청 전에는 추가 송수신·다운로드·계측을 진행하지 않는다.
- 남은 실기 확인: VCC–GND/A–B 저항, TX/RX 방향, USB 변환기 구조·A/B 연결. 아직 점검 통과로 기록하지 않는다. 현재 펌웨어는 PB7 명령 수신 전까지 PB6를 입력으로 유지한다.
- [구현·시험·제조사 근거](설계/RS485-WPF-구현기록.md). 최신 실행 파일은 software/build/UltrasonicMonitor/bin/Debug/net10.0-windows/UltrasonicMonitor.exe이며 RS-485/COM4 화면을 실행해 둔 상태다.

## 다음 재개 시 디버깅 계획 — 아직 미실행

목적: PC의 PING이 끊기는 구간을 특정하고 실제 RS-485 센서 응답과 WPF 표시까지 확인한다. 수신 카운터 0만으로 물리 신호가 없거나 배선 불량이라고 확정하지 않는다.

1. **연결 상태 확정:** PC USB 변환기 종류·COM 번호, 케이블 양쪽 A/B, TX/RX 교환 후 최종 핀 연결을 확인한다. 로직애널라이저 모델·입력 허용 전압·사용 프로그램도 확인한다.
2. **멀티미터 확인:** 전원 분리 상태에서 배선 도통·단락을 확인하고, 사용자가 전원을 인가한 뒤 AT044 VCC–GND 전압을 측정한다. 기존 연결의 기대값은 약 3.3 V이며 실제값은 미측정이다. 측정 모드와 프로브 단자를 확인한다.
3. **신호 캡처:** 입력 허용 범위를 확인한 로직애널라이저로 TTL 쪽 모듈 출력과 PB7을 관찰한다. 필요하면 PB6도 함께 확인한다. 일반 로직 입력을 A/B에 바로 연결하지 않는다. Codex가 동일한 PING을 전송하고 115200 8N1 수신 내용과 파형을 비교한다. 실제 캡처 설정·접지는 장비 확인 후 정한다.
4. **결과에 따른 원인 분리:** 모듈 TTL 출력부터 신호가 없으면 PC 변환기·A/B 경로·모듈 전원/방향을 확인한다. 모듈 출력에는 있고 PB7에는 없으면 그 사이 배선을 확인한다. PB7에 정상 PING이 있는데 카운터가 0이면 펌웨어 핀 설정·USART·인터럽트 경로를 점검한다. 수신은 되지만 내용이 틀리면 통신 설정·신호 품질을 확인한다.
5. **응답과 UI 검증:** 정상 PING 수신 후 명령 해석→PB6 응답→PC 수신 순서를 확인한다. PONG이 확인되면 센서 명령, 반복 요청, WPF 표시·시간 초과/재연결을 확인한다. 조건·실제값·파형·로그를 함께 기록하며 센서 오류 응답을 측정 성공으로 처리하지 않는다.

완료 조건: 실제 RS-485 경로의 PING/PONG, 센서 응답 및 그 결과의 WPF 표시를 증거로 확인. 물리 계측은 사용자가 수행하고 Codex는 PC 송신·펌웨어 분석·필요한 수정·로그 정리를 맡는다.

### 2026-09-14 — USART1 클록 펌웨어 다운로드와 실기 확인

- 사용자 요청으로 STM32CubeProgrammer 2.23.0 / ST-LINK V2J48M35 / SWD 4 MHz를 사용해 연결된 NUCLEO-F401RE에 현재 Debug ELF를 다운로드했다. 빌드는 최신 상태였고, 작업 트리의 기존 spi2.c 변경은 공백 한 칸 추가였다.
- 다운로드 전 Hot Plug에서 RCC_AHB1ENR=0x00000007, RCC_APB2ENR=0x00000000 확인. Under Reset 다운로드·바이트 검증 성공 후 소프트웨어 리셋을 실행했다.
- 재시작 후 Hot Plug 측정: RCC_AHB1ENR=0x00000007(GPIOBEN[1]=1), RCC_APB2ENR=0x00000010(USART1EN[4]=1). 기대한 클록 활성화 상태와 일치한다.
- GPIOB_MODER=0xA9000280에서 MODER6[13:12]=00, MODER7[15:14]=00으로 PB6/PB7 입력 상태를 확인했다. USART1_CR1=0에서 UE[13]/TE[3]/RE[2]=0으로 USART1 송수신 비활성 상태를 확인했다. 통신 성공 판정은 하지 않는다.
- ST-LINK 표시 전압 3.25–3.26 V는 AT044 전원 단자 실측값이 아니다. 새 물리 전원 인가는 수행하지 않았으며 이미 연결된 보드에 다운로드·리셋했다. 기존 저항·TX/RX 방향 미확인 상태는 유지한다.
- [원시 결과 로그와 ELF SHA256](측정/2026-09-14-USART1-클록/다운로드-클록확인-로그.txt). PowerShell의 UTF-8/UTF-16 혼합 저장을 발견해 기존 출력 내용을 유지하며 UTF-8로 통일했다.
- 근거: [RM0368 Rev 6](references/rm0368-stm32f401xb-c-d-e-mb-reference-manual-stmicroelectronics.pdf) §6.3.9 RCC_AHB1ENR p.118–119, §6.3.12 RCC_APB2ENR p.122–123, §8.4.1 GPIOx_MODER p.158, §19.6.4 USART_CR1 p.551–553. 이번 로컬 PDF의 문서 표기와 PDF 페이지는 같다.

- 안내: 서로 꼬인 한 쌍만 A/B에 사용하고, 양 끝에서 같은 도체인지 필요하면 케이블을 기기에서 분리해 도통 측정으로 식별한다. 주황색=A+, 선택한 짝의 흰색=B-는 Codex가 제시한 구분 방법이며 실제 배선 완료를 뜻하지 않는다.
- 남는 두 심선과 편조체 끝은 각각 절연해 두는 임시 방식을 안내했다. 실드·신호 기준 접지의 최종 연결은 USB 변환기 구조 확인 전 미정이다.
- 사용자가 AT044에 달았던 것을 뺐다며 직접 납땜할지 물었다. 대화 문맥상 A/B 단자 제거로 해석했으나 제거 범위·패드 상태는 미검증이다.
- 안내: A/B 패드가 온전하면 직접 납땜할 수 있다. 전원을 모두 분리하고 케이블 끝과 패드 예비 납땜, 짧은 가열, 인접 패드 단락 확인, 케이블 외피의 별도 고정이 필요하다. 직접 납땜 완료·전원 인가·저항 측정 결과는 아직 없다.

### 2026-09-14 — TX/RX 연결 완료 보고

- 직전 추정 배선 표에 대해 사용자가 “오케이 연결함 다음”이라고 보고했다. AT044 TXD↔PB6, RXD↔PB7 연결 완료로 기록한다.
- 이는 물리 연결의 사용자 보고이며 AT044 신호 방향 검증 또는 통신 성공 보고는 아니다.
- 다음 작은 과제로 전원 분리 상태의 AT044 VCC–GND 저항 측정을 안내했다. 측정값은 아직 없으며 전원 인가를 안내하지 않았다.

### 2026-09-14 — 사용자 요청으로 TX/RX 추정안 선택

- 사용자가 Codex에게 추측해서 TX/RX 배선을 정해 달라고 요청했다.
- 임시 선택: STM32 USART1 TX=PB6(CN10-17)→AT044 TXD, AT044 RXD→STM32 USART1 RX=PB7(CN7-21).
- 가정: 모듈의 TXD 표기는 RS-485 송신용 TTL 입력, RXD 표기는 수신한 데이터의 TTL 출력이다. 제공 이미지로 입출력 방향을 확정한 것은 아니다.
- 추정과 다르면 출력끼리 연결될 수 있으므로, 배선은 전원 분리 상태로 진행하며 전원 인가·송수신 구동 전 방향 확인이 남아 있다. 펌웨어 변경·실제 배선 완료·통신 성공은 아직 없다.

### 2026-09-14 — TX/RX를 제외하고 먼저 배선

- 사용자 결정: TX/RX 연결은 제외하고 나머지 배선을 먼저 진행한다.
- 안내 범위: 전원을 분리한 상태에서 NUCLEO CN7-16(3.3V)→AT044 VCC, CN7-20(GND)→AT044 TTL 쪽 GND. PC용 변환기의 A+/B- 표기가 일치하면 AT044 A+↔변환기 A+, B-↔B-로 연결한다.
- AT044 버스 쪽 접지 기호 단자와 TXD/RXD는 이번 연결에서 비워 둔다. USB 변환기의 5V를 AT044 VCC에 추가 연결하지 않는다. 전원 인가는 배선 점검 후 별도 진행한다.
- 배선 완료·전원 인가·측정·통신 성공 보고는 아직 없다.

### 2026-09-14 — RS-485 배선 안내

- 사용자 요청: RS-485 배선을 직접 안내해 달라고 요청했다.
- Codex 제안: 기존 USART2 진단(PA2/PA3)과 초음파(PA10)를 유지하기 위해 USART1의 PB6(TX)/PB7(RX)를 사용한다. 사용자 선택·배선 완료로 판정하지 않는다.
- NUCLEO 위치: PB6=CN10-17, PB7=CN7-21, 3.3V=CN7-16, GND=CN7-20. 근거: [UM1724 Rev 17](references/dm00105823-nucleo-f401re-user-manual-stmicroelectronics.pdf), Hardware layout and configuration, Table 29 p.59; [DS10086 Rev 5](references/DS_stm32f401re.pdf), Pinouts and pin description, Table 8 p.43 및 Table 9 p.46. 모두 문서 표기와 PDF 페이지가 같다.
- [AT044 공급사 자료](https://www.devicemart.co.kr/goods/view?no=1361352)의 상세 이미지에서 VCC/TXD/RXD/GND, A+/B-/접지 단자를 확인했다. 3.3V 지원·자동 방향 제어·R0 단락 시 120Ω 종단 활성화 설명을 확인했다. 공급사 이미지에 TXD/RXD 입출력 방향을 명시한 회로도는 없어 실제 모듈의 방향 대조는 남아 있다.
- 전원은 NUCLEO 3.3V→VCC, GND→TTL 쪽 GND로 제안한다. 신호선은 AT044 TXD가 입력, RXD가 출력인 경우 PB6→TXD, RXD→PB7로 연결한다. PC 쪽은 A+↔A+, B-↔B- 기준이며 실제 USB 변환기 모델·단자 확인은 남아 있다.
- 현재 USART1 펌웨어 구현·전원 인가·배선 완료·통신 성공은 기록하지 않는다. 이번 안내는 전원을 분리한 상태의 배선 준비다.

### 2026-09-14 — RS-485 재개 위치 정정
