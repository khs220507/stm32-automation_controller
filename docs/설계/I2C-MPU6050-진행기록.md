# I2C·MPU6050 진행 기록

## 문서 목적

이 문서는 NUCLEO-F401RE와 SZH-EK007(GY-521형 MPU6050)의 I2C Bring-up 과정에서 현재 진행 위치와 다음 시작점을 남긴다. 공식 요구사항과 시험 판정의 원본은 `docs/records/펌웨어-프로젝트-요구사항.xlsx`이며, 이 문서가 이를 대체하지 않는다.

## 다음 대화에서 가장 먼저 할 일

1. `VERSION`과 공식 요구사항 문서의 개정·상태를 확인한다.
2. 이 문서의 **데이터시트 검토 순서**를 1단계부터 수행한다.
3. PB8/PB9 핀 초기화 코드를 검토한 뒤 **핀 초기화 검증 절차**를 수행한다.

현재 재개 위치는 **UM1724에서 D15=PB8, D14=PB9를 확인하는 단계**다.

## 관련 요구사항

- `FW-REQ-013`: MPU6050 데이터 수집과 경고 기능 — 상태 `의뢰`
- `FW-REQ-022`: 센서 통신 제한시간과 무한 대기 방지 — 상태 `의뢰`
- `FW-REQ-047`: CMSIS 레지스터 방식의 I2C 베어메탈 구현 — 상태 `합의`
- `FW-REQ-050`: I2C 파형과 타이밍 계측 — 상태 `의뢰`

요구사항의 상세 문구와 최신 상태는 공식 요구사항 문서에서 직접 확인한다.

## 현재 확인된 사실

- 사용 모듈: SZH-EK007, GY-521형 MPU6050
- 사용자 확인일: 2026-09-05
- 배선:
  - MPU6050 `VCC` → NUCLEO `3V3`
  - MPU6050 `GND` → NUCLEO `GND`
  - MPU6050 `SCL` → NUCLEO `D15/PB8`
  - MPU6050 `SDA` → NUCLEO `D14/PB9`
  - `XDA`, `XCL`, `AD0`, `INT` 미연결
- 사용자가 전압이 정상적으로 측정된다고 확인했다.
- 정확한 실측 전압값은 제공되지 않았으므로 기록하지 않았고 시험 통과 판정도 하지 않았다.
- `i2c1_pins_init()` 코드와 설명 주석을 작성했다.
- ARM GCC 문법 검사는 통과했다.
- CubeIDE Clean Build, 다운로드, 레지스터 관찰 및 실기 검증은 아직 수행 결과가 없다.

## 데이터시트 검토 순서

### 1. NUCLEO 커넥터와 MCU 핀 대응

[NUCLEO-F401RE 사용자 매뉴얼](../references/dm00105823-nucleo-f401re-user-manual-stmicroelectronics.pdf)에서 다음을 검색한다.

```text
Figure 18. NUCLEO-F401RE
```

확인할 내용:

```text
D15 = PB8
D14 = PB9
```

### 2. PB8/PB9 Alternate Function 확인

[STM32F401RE 데이터시트](../references/DS_stm32f401re.pdf)에서 다음을 검색한다.

```text
Table 9. Alternate function mapping
```

확인할 내용:

```text
PB8 + AF4 = I2C1_SCL
PB9 + AF4 = I2C1_SDA
```

### 3. I2C 핀의 GPIO 구성 확인

[RM0368 Reference Manual](../references/rm0368-stm32f401xb-c-d-e-mb-reference-manual-stmicroelectronics.pdf)에서 다음을 검색한다.

```text
Table 24. Port bit configuration table
```

확인할 내용:

```text
MODER  = 10 : Alternate Function
OTYPER = 1  : Open-drain
PUPDR  = 00 : No pull-up/down
```

### 4. GPIOB 클록 활성화 확인

RM0368에서 다음을 검색한다.

```text
RCC AHB1 peripheral clock enable register
GPIOBEN
```

확인할 내용:

```text
RCC_AHB1ENR bit 1 = GPIOBEN
```

### 5. GPIO 레지스터 필드 확인

RM0368에서 다음 순서로 확인한다.

```text
GPIOx_OTYPER
GPIOx_OSPEEDR
GPIOx_PUPDR
GPIOx_AFRH
GPIOx_MODER
GPIOx_IDR
```

대상 필드:

```text
OT8, OT9
OSPEED8, OSPEED9
PUPD8, PUPD9
AFSEL8, AFSEL9
MODER8, MODER9
IDR8, IDR9
```

### 6. CMSIS 매크로와 코드 대조

`stm32f401xe.h`에서 다음 매크로를 검색하고 [i2c1.c](../../firmware/automation_controller/Src/i2c1.c)의 사용 위치와 대조한다.

```c
RCC_AHB1ENR_GPIOBEN
GPIO_OTYPER_OT8
GPIO_OSPEEDR_OSPEED8_1
GPIO_PUPDR_PUPD8
GPIO_AFRH_AFSEL8_2
GPIO_MODER_MODER8_1
```

## 핀 초기화 검증 절차

1. CubeIDE에서 프로젝트를 Refresh한다.
2. Project Clean 후 Build한다.
3. [app_state.c](../../firmware/automation_controller/Src/app_state.c)의 `i2c1_pins_init()` 다음 줄에 중단점을 설정한다.
4. Debug를 시작하고 중단점에서 다음 표현식을 관찰한다.

```c
(RCC->AHB1ENR >> 1) & 0x1U
(GPIOB->MODER >> 16) & 0xFU
(GPIOB->OTYPER >> 8) & 0x3U
(GPIOB->OSPEEDR >> 16) & 0xFU
(GPIOB->PUPDR >> 16) & 0xFU
GPIOB->AFR[1] & 0xFFU
(GPIOB->IDR >> 8) & 0x3U
```

기대값:

| 관찰 항목 | 기대값 | 의미 |
|---|---:|---|
| GPIOB 클록 | `0x1` | GPIOB 활성화 |
| MODER8·9 | `0xA` | PB8/PB9 Alternate Function |
| OTYPER8·9 | `0x3` | PB8/PB9 Open-drain |
| OSPEEDR8·9 | `0xA` | PB8/PB9 High speed |
| PUPDR8·9 | `0x0` | 내부 pull-up/down 없음 |
| AFR8·9 | `0x44` | PB8/PB9 AF4 |
| IDR8·9 | `0x3` | SCL/SDA 유휴 High |

I2C1 주변장치를 아직 활성화하지 않았으므로 이 단계에서는 SCL 클록 펄스가 없어야 한다. 레지스터 관찰값과 실제 SCL/SDA 전압을 확인하기 전에는 핀 초기화를 통과로 판정하지 않는다.

## 이후 작업

핀 초기화 검증이 끝난 뒤에만 다음 작은 과제로 진행한다.

1. 현재 APB1 클록 확인
2. I2C1 주변장치 클록 활성화
3. 100 kHz용 `CR2`, `CCR`, `TRISE` 계산과 설정
4. 유한 제한시간을 갖는 START, 주소 전송 및 ACK 확인
5. MPU6050 `WHO_AM_I(0x75)` 읽기와 기대값 `0x68` 확인
6. 로직 분석기로 START, 주소, ACK, 데이터 및 STOP 파형 측정
