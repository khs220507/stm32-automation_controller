# RS-485 → WPF 구현 기록

2026-09-14 사용자 요청으로 Codex가 펌웨어부터 WPF 화면까지 구현했다. 사용자는 코드 분석을 나중에 진행하기로 했다. 공식 요구사항·시험 판정을 대체하지 않는 구현 및 실행 기록이다.

## 범위와 현재 결과

- VERSION: 프로젝트 0.1.0-draft, 요구사항 0.2-draft. 공식 펌웨어 요구사항의 부분 승인·검토 대기 상태와 FW-REQ-005/019/022/047을 확인했다. RS-485 확장은 최신 사용자 요청에 따라 진행했으며 공식 문서·버전·승인 상태는 변경하지 않았다.
- PC↔보드 1:1 RS-485에서 기존 ASCII 명령과 CRLF 응답을 사용한다. Modbus RTU·주소·CRC·다중 노드는 구현 범위에 포함하지 않았다.
- 펌웨어와 WPF 구현·빌드·호스트 검증 완료. ST-LINK 다운로드와 바이트 검증 성공.
- **실제 RS-485 통신은 아직 확인하지 못했다.** COM4(CH340)를 열고 PING을 보냈으나 800 ms 실기 스크립트 및 500 ms WPF 대기에서 응답이 없었다. USART1 수신·오류 카운터는 모두 0이었다.
- 실제 WPF에서 RS-485/COM4 선택, 연결 시 PING 전송, 무응답 표시와 연결 해제, 별도 COM3 UART PONG 표시를 확인했다. 모형 시험에서 PONG·거리·가속도·센서 오류 표시를 확인한 것과 구분한다.
- 실제 TCP에서 PONG, W5500=4, 센서 식별값=114, 가속도 설정 및 원시값 응답을 확인했다. RS-485 센서 측정 성공으로 해석하지 않는다.

## 연결과 처리

- 사용자 보고 배선: AT044 3.3V/GND, TXD↔PB6(CN10-17), RXD↔PB7(CN7-21), A/B 케이블 직접 납땜. TXD/RXD 입출력 방향은 제품 라벨을 바탕으로 한 이전 추정이며 실물 확인 전이다. PC 쪽 변환기의 A/B 연결과 COM4 장치 용도를 사용자에게 질문한 상태다.
- USART1: PCLK2=16 MHz 조건, 115200 8N1. PB7을 AF7 수신으로 먼저 설정하며 PB6는 입력으로 둔다. PB7에서 명령을 받아 응답을 구성했을 때만 PB6 AF7 송신을 활성화한다. 출력 간 충돌 가능성을 줄이는 초기 동작이며 배선 검사 자체를 대체하지 않는다.
- 수신 IRQ에서 완성 줄 하나를 64바이트 메일박스로 넘긴다. 본문 최대 62바이트+CRLF. 다음 완성 줄이 겹치면 덮어쓰지 않고 폐기 횟수를 누적한다. PC는 요청 하나의 응답을 기다린 뒤 다음 요청을 보낸다.
- 부분 입력의 바이트 간격이 100 ms 이상이면 다음 바이트에서 이전 부분 줄을 버린다. 길이 초과·ORE/NF/FE/PE가 있는 줄은 폐기하고 다음 줄로 복구한다. 송신 중 들어오는 에코는 제외한다.
- 응답 전체를 최대 128바이트로 모은 뒤 송신한다. 송신 앞뒤 각 1 ms의 전환 여유를 두고 TXE와 TC를 확인한다. 타이머 동작 조건에서 송신 대기 총 한도는 20 ms다. 지연값은 구현값이며 모듈 파형으로 검증한 값은 아니다.
- TCP와 RS-485는 수신 파서를 따로 유지하고, 완료된 명령의 응답을 요청한 경로로 돌려준다. 두 경로에 명령이 동시에 있으면 번갈아 처리한다. TCP 세션 초기화가 RS-485 부분 입력을 지우지 않는다. TCP 대기 상태 연결 종료는 독립 진단의 가속도 설정을 무효화하지 않는다.
- RS-485에서는 PING, GET_STATUS, CHECK_W5500, CHECK_MPU6050, WAKE_MPU6050, CONFIG_ACCEL, READ_ACCEL, CHECK_HCSR04를 기존 처리에 연결했다. 기존 TCP의 START/STOP 자동 출력은 반이중 버스의 요청·응답 방식과 달라 RS-485에서 UNSUPPORTED로 응답한다. WPF 반복 측정은 CHECK/READ 요청을 순서대로 보내므로 사용 가능하다.
- WPF는 주 연결을 TCP 또는 RS-485 중 하나로 선택한다. UART2 독립 진단은 별도로 유지하고 같은 COM 포트의 중복 사용을 차단한다. RS-485 열기와 보드 응답 확인을 구분해 표시하며 응답 시간 초과·수신 오류·송신 오류 시 연결을 정리한다. 이전 포트 콜백과 미완성 응답을 재연결에 섞지 않는다.

## 남은 확인

PC USB-RS485 변환기 용도·A/B 연결, AT044 전원·공통 기준·TX/RX 방향과 납땜 상태를 실물에서 확인한 뒤 다시 요청·응답을 시험해야 한다. 저항·종단·바이어스·실드 접속·파형·장거리·장시간 동작은 검증하지 않았다. 통신 구현 및 모형 시험 통과를 이 항목의 통과로 확대하지 않는다.
